# Pet pack contract

A pet pack is a folder. The required part is the Codex pet format so
packs work in Codex, petdex, agentpet and CoPet unchanged. Everything
sidepaw adds is optional and ignored by other readers.

```
my-cat/
  pet.json            required
  spritesheet.webp    required (or .png)
  persona.json        optional, sliders and tags
  persona.md          optional, free text
  lines.json          optional, generated local lines per state
  anim/               optional, Pack v2 animation layer (planned)
  voice/              optional, sound pack
```

## pet.json

```json
{
  "id": "my-cat",
  "displayName": "My Cat",
  "description": "A grey cat that judges your npm installs.",
  "spritesheetPath": "spritesheet.webp",
  "x-sidepaw": {
    "version": 1,
    "license": "CC-BY-NC-SA-4.0",
    "attribution": [
      { "role": "character", "name": "someone", "url": "https://…" }
    ],
    "persona": "persona.json",
    "personaText": "persona.md",
    "lines": "lines.json",
    "voice": "voice/"
  }
}
```

The four top-level keys are the Codex format. `x-sidepaw` is ours.
`license` and `attribution` are required for packs in this repository
and strongly recommended elsewhere; the loader shows them on the pet's
page.

## spritesheet

Codex layout, unchanged: 1536 by 1872 pixels, 8 columns by 9 rows of
192 by 208 cells, transparent background, unused cells fully
transparent. petdex's v2 sheets (1536 by 2288, two more rows) are
accepted too; sidepaw draws the first nine rows. Rows, top to bottom:

| Row | State | sidepaw maps from |
| --- | --- | --- |
| 0 | idle | Idle |
| 1 | running-right | Tool (moving) |
| 2 | running-left | Tool (moving) |
| 3 | waving | Done |
| 4 | jumping | Done (first frame of a long task) |
| 5 | failed | Error |
| 6 | waiting | Waiting |
| 7 | running | Thinking |
| 8 | review | Tool (read, search) |

Frame counts per row and the 6 frames at 1100 ms default loop follow the
Codex convention. The loader validates dimensions and transparency and
re-encodes the image before use.

## persona.json

```json
{
  "version": 1,
  "name": "Mochi",
  "callsUser": "boss",
  "species": "cat",
  "sliders": {
    "talkative": 0.4,
    "sharp": 0.8,
    "proactive": 0.5,
    "serious": 0.3,
    "confident": 0.7,
    "clingy": 0.2
  },
  "strengths": ["observant", "encouraging"],
  "flaws": ["lazy", "forgetful"],
  "catchphrases": ["again?"],
  "avoid": ["politics"],
  "language": "zh-CN"
}
```

Sliders are 0 to 1. Each strength and flaw tag maps to a short behaviour
rule in the compiler. Unknown tags are kept as plain words in the
prompt. `language` is optional: without it the pet speaks the app's UI
language, and in chat it answers in whatever language the user writes
either way. The JSON Schema is `persona.schema.json`.

## persona.md

Free text appended verbatim to the compiled system prompt after the
slider and tag section. Use it for backstory, voice samples, and hard
rules. Keep it under 1500 characters; the editor warns above that.

## lines.json

Generated by the compiler, editable by hand. Keys are state names plus
interaction names (`click`, `drag`, `drop` for a file dropped on the
pet); values are arrays of strings. The renderer picks uniformly at
random, avoiding the last three used. A missing `drop` key falls back
to `click`; other missing keys are silent.

`morning` through `chatter` are what the pet says unprompted (see
`docs/architecture.md`, proactive lines). `report` lines may use
`{tools}`, `{turns}`, `{errors}`, `{sessions}` and `{waited}` (minutes),
filled from today's counters.

```json
{
  "version": 1,
  "generatedFrom": "sha256 of persona.json + persona.md",
  "idle": ["…"],
  "thinking": ["…"],
  "tool.shell": ["…"],
  "tool.edit": ["…"],
  "waiting": ["…"],
  "done": ["…"],
  "error": ["…"],
  "click": ["…"],
  "drag": ["…"],
  "drop": ["…"],
  "morning": ["…"],
  "night": ["…"],
  "waiting_long": ["…"],
  "errors": ["…"],
  "long_done": ["…"],
  "report": ["Today: {tools} tool calls, {errors} errors."],
  "break": ["…"],
  "back": ["…"],
  "chatter": ["…"]
}
```

When `generatedFrom` no longer matches the persona files, the app
offers to regenerate.

Installed packs live in `~/.sidepaw/packs/<id>/`: `pet.json`, the
spritesheet, any of `persona.json`, `persona.md` and `lines*.json`
that came with it, and a `source.json` sidepaw writes (where it came
from and who made it). Installing reads only those files from a zip or
folder, checks the manifest and the sheet's size from its header, caps
each file (20 MiB for the sheet, 1 MiB for text) and swaps the folder
in whole. An id that is not lowercase letters, digits and hyphens is
turned into one. A pack without lines speaks the bundled pack's lines
until the user generates its own; one without a persona starts from a
blank persona named after the pack.

The app never writes into a pack. `persona.json`, `persona.md` and
`lines.json` saved from the setup window go to
`~/.sidepaw/pets/<id>/` and override the pack's copies of those files;
removing them restores the pack's defaults.

Optional: `lines.<lang>.json` next to `lines.json` (for example
`lines.zh-CN.json`) is used instead when the UI language matches. The
`lang` tag follows the same form as `persona.json`'s `language`.

## voice/

Optional MP3 or OGG files named after the same keys as `lines.json`
(`click.mp3`, `error.mp3`). Missing files are silent.
